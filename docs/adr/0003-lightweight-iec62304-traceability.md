# 轻量需求追踪：IEC 62304 的最小落地

项目是注册取证产品。决定：不引入完整 ALM 工具链，而是用"需求编号 ↔ 模块/测试用例"的 Markdown 追踪矩阵（`docs/requirements.md`），每条需求编号（`REQ-xxxx`）在代码注释与单元测试用例名中引用。

**Considered Options**: 完整 62304 工具链（Polarion / Helix 等）——重、贵，现阶段无外部审计压力；拒绝。完全不做追踪——取证阶段补需求溯源会非常痛苦；拒绝。

**Consequences**: 新功能/缺陷修复的提交需同步更新需求矩阵；单元测试用例名携带需求编号，CI 可自动核对覆盖。
